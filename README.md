# AntiSlop MVP

Веб-инструмент для проверки изображений на признаки AI-генерации. Базовый анализ выполняется локально; по желанию изображение параллельно проверяется через настроенные внешние API.

Изображение можно выбрать, перетащить в окно или вставить напрямую из буфера через `Ctrl+V` / `Cmd+V`.

## Интерфейс

Первый экран — тёмный лендинг с анимированным фоном и кнопкой «Проверить изображение». Кнопка сразу открывает выбор файла; затем интерфейс переводит к превью и запуску анализа. Доступны также drag-and-drop и вставка из буфера. Во время анализа видны сканирующая линия и текстовый статус. Ошибки показываются рядом с формой, а при сбое проверку можно повторить.

Результат содержит крупный итоговый процент, понятное объяснение, число ответивших моделей и согласованность источников. Ниже — пять направлений анализа; технический отчёт с метаданными и диагностическими картами раскрывается по желанию. Если нет ни модельных ответов, ни положительных признаков происхождения, показано «Недостаточно данных».

Интерфейс адаптирован для телефона, планшета и компьютера, поддерживает клавиатуру и настройку уменьшения движения. Canvas-фон ограничен 30 кадрами/с и приостанавливается вне экрана. Шрифты Manrope и Unbounded хранятся локально с лицензиями OFL; сторонние библиотеки для анимации не нужны.

## Поиск по картинке в интернете

Блок «Поиск по картинке» расположен сразу под подробным отчётом. Яндекс и Google открываются в новой вкладке с уже выбранным изображением: выбирать и загружать файл повторно не нужно. До анализа поиск также доступен после выбора файла.

Браузер подготавливает JPEG-копию до 1280 px / 2 МиБ и отправляет её в Яндекс только после нажатия кнопки поиска. Для Google используется URL этой копии: прямой POST в Google из стороннего сайта блокировался с HTTP 403. Копия кэшируется для текущего файла на пять минут, чтобы при переключении поисковика не загружать её повторно. Исходный файл для анализа и C2PA не меняется.

API-ключи, платные API и публикация изображения на сервере AntiSlop не нужны. Это отдельное действие пользователя, доступное и при `remote=false`; автоматический анализ в этом режиме остаётся локальным. Результаты внешнего поиска не меняют итоговый процент.

Проверена реальная выдача Яндекса с найденными похожими изображениями и сайтами. Google по GET-переходу принимает URL и открывает поиск с HTTP 200 без прежнего 403; в проверочной сети затем запрашивает капчу. Браузерные интерфейсы поисковиков могут меняться. Таймаут и ошибки показываются рядом с кнопками; смена/сброс файла отменяют незавершённый поиск.

## Что проверяется

- EXIF, XMP, IPTC и текстовые метаданные;
- PNG text chunks, JPEG comments и читаемые строки контейнера;
- C2PA / Content Credentials / JUMBF-сигнатуры;
- маркеры Midjourney, DALL·E, Stable Diffusion, Firefly, Imagen/Gemini, Ideogram, Leonardo, Runway, NovelAI, Flux и других сервисов;
- эвристика контрастного бейджа в углах для последующей ручной проверки.
- независимые ML-детекторы Hive, Sightengine, AI or Not и WasItAI.
- локальный Frontier ViT и явная сводная вероятность AI-генерации;
- опциональный смысловой анализ сцены через OpenAI Vision (анатомия, физика, текст и противоречия сюжета);
- опциональная проверка SynthID и C2PA через OpenAI Content Provenance API;
- криптографическая проверка C2PA через официальный CAI SDK;
- ELA-карта, шумовой остаток, частотный спектр и карта повторяющихся паттернов;
- SHA-256, perceptual hash и difference hash для поиска копий и вариантов;
- проверка логики EXIF-полей.

Инструмент не заявляет, что определяет любую AI-картинку. Метаданные можно удалить. Проверка SynthID через OpenAI распознаёт только поддерживаемые OpenAI сигналы и не покрывает все изображения Google или других генераторов. Отсутствие метки не подтверждает подлинность.

## Запуск

Требуется Python 3.11 или новее. OAuth-скрипт рассчитан на macOS/Linux.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python main.py
```

Открыть `http://127.0.0.1:8000`.

## Проверка серии снимков

Вкладка «Серия фото» или `POST /api/analyze-set` (`files[]`, 2–6 снимков, `mode=scene|person`):

- **Одна сцена** — проверяет, согласуются ли ракурсы геометрически как реальная 3D-съёмка (SIFT + MAGSAC, восстановление позы камеры), подсвечивает несовпадающие зоны, сравнивает EXIF серии.
- **Один человек** — сравнивает лица (YuNet + SFace), ищет «вклеенное» лицо, одинаковое пиксель в пиксель на разных фонах, и расхождение оценок лица и фона.

Работает локально, без API-ключей. Результат — «согласовано / не согласуется / недостаточно данных», причины и рекомендации действий. Согласованность серии не доказывает подлинность.

## Оценка качества

```bash
.venv/bin/pip install -r requirements-eval.txt
.venv/bin/python -m evaluation fetch            # часть OpenFake test (~300 МБ, CC BY-NC 4.0)
.venv/bin/python -m evaluation run              # отчёт в eval_reports/<время>/report.md
.venv/bin/python -m evaluation run --folder my_set   # my_set/real/**, my_set/ai/<генератор>/**
```

Отчёт содержит ROC-AUC, PR-AUC, recall/FPR при пороге 0.65, FPR при recall 95%, калибровку и срезы по генераторам и пережатию. Модель частично обучалась на OpenFake, поэтому общие цифры завышены — подробности в `AGENTS.md`, раздел 10.

## Подключение API

Скопируйте `.env.example` в `.env` и заполните ключи тех сервисов, которые хотите использовать:

```bash
cp -n .env.example .env
```

После изменения `.env` перезапустите сервер.

| Сервис | Переменные |
| --- | --- |
| Hive | `HIVE_API_KEY` |
| Sightengine | `SIGHTENGINE_API_USER`, `SIGHTENGINE_API_SECRET` |
| AI or Not | `AIORNOT_API_KEY` |
| WasItAI | `WASITAI_API_KEY` |
| ChatGPT Vision | OAuth: `.venv/bin/python chatgpt_login.py`; модель `CHATGPT_VISION_MODEL` |
| OpenAI SynthID / C2PA | `OPENAI_API_KEY` (только проверка происхождения) |

Ключи читаются только сервером и не возвращаются в браузер. Запросы выполняются параллельно с таймаутом 25 секунд; смысловой анализ имеет общий таймаут 90 секунд. Переключатель «Дополнительная проверка» над кнопкой анализа позволяет провести только локальную проверку. Рядом явно указано, будет ли изображение передано внешним сервисам.

Проверка OpenAI SynthID / C2PA отправляет исходный файл без ресайза или перекодирования в `POST /v1/content_provenance_checks`. Поддерживаются PNG, JPEG и WebP; другие форматы пропускаются. Как и остальные внешние проверки, она выполняется только при `remote=true`. Для локального режима выберите анализ без внешних API.

В полном отчёте сохраняются отдельные результаты SynthID и C2PA, а также доступные сведения о модели, времени генерации, издателе и состоянии валидации. API возвращает признаки происхождения, а не вероятность AI. Обнаруженный SynthID или обнаруженный C2PA со статусом `trusted` / `valid` добавляют один provenance-сигнал `0.99` в общее среднее. Этот сигнал общий с локальной проверкой C2PA, поэтому одна и та же информация не учитывается дважды. `not_detected` не снижает итоговую оценку. Остальные вероятностные результаты и metadata-сигнал `0.95` объединяются по прежним правилам.

Доступность API зависит от организации OpenAI. Ответы 400 (неподдерживаемый или заблокированный файл), 404 (API недоступен организации), 429 (лимит запросов), таймауты и другие ошибки показываются в отчёте и не прерывают анализ. Автоматических повторов нет. Контракт: [руководство OpenAI](https://developers.openai.com/api/docs/guides/content-provenance), [справочник API](https://developers.openai.com/api/reference/resources/content_provenance_checks/methods/create).

Illuminarty не публикует общий контракт API и остаётся недоступным. Покрытие других генераторов через SynthID требует отдельного поддерживаемого API.

## Вход для смыслового анализа

`OPENAI_API_KEY` не используется для смыслового анализа. Вход основан на предоставленных скриптах Jarvis и официальном [Sign in with ChatGPT](https://developers.openai.com/siwc/token-sharing-open-source/sign-in):

```bash
.venv/bin/python chatgpt_login.py
```

В браузере войдите в нужный аккаунт и разрешите "Use your ChatGPT plan". Пароль вводится только на странице OpenAI. Скрипт проверяет state, PKCE, подпись ID-токена, nonce, аккаунт и scopes. Регистрация и обновляемая сессия сохраняются в `.antislop-auth/registration.json` и `.antislop-auth/credentials.json` с правами 0600; каталог имеет права 0700 и исключён из Git. Не публикуйте эти файлы. Повторный вход использует прежнюю регистрацию и отказывается перезаписывать её другим аккаунтом.

После входа обновите страницу AntiSlop. При включённых внешних проверках каждое изображение отправляется в модель `gpt-6-luna`; имя можно изменить через `CHATGPT_VISION_MODEL` с перезапуском сервера. Модель должна быть доступна вашему аккаунту и поддерживать изображения и JSON Schema. Используется [Responses API с лимитами плана](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference), `store=false`, `stream=true`. При исчерпании лимитов или ошибке входа платный API не вызывается. Доступность этого потока зависит от аккаунта и текущих ограничений OpenAI.

Для анализа создаётся JPEG-копия до 1280px по длинной стороне с учётом EXIF-ориентации; оригинал по-прежнему передаётся без изменений в SynthID. Смысловой запрос не получает инструменты. Одновременно обрабатывается одно изображение; автоматически повторять запросы сервис не будет. Refresh-токен обновляется под файловой блокировкой и сохраняется даже при отмене исходного запроса.

Текст собирается из SSE-событий `response.output_text.delta` / `done`: поток OAuth может завершиться с пустым `response.completed.output`. Даже при наличии полного JSON ответ принимается только после успешного `response.completed`.

Результат доступен в `api_results[id=openai_vision].analysis`, версия контракта `1.0`:

```json
{
  "schema_version": "1.0",
  "probability": 75,
  "assessment": "likely_ai",
  "explanation": "Краткое обоснование по наблюдаемым деталям.",
  "signals": [{
    "category": "anatomy",
    "observation": "Наблюдаемая анатомическая несогласованность.",
    "explanation": "Почему эта деталь заслуживает проверки.",
    "alternative_explanation": "Возможен монтаж или перекрытие объектов.",
    "strength": "moderate",
    "region": {"x1": 0.1, "y1": 0.2, "x2": 0.4, "y2": 0.7}
  }],
  "limitations": ["Мелкие детали могут быть утрачены при уменьшении."]
}
```

Схема в `vision_contract.py` используется одновременно для structured output и серверной проверки. Максимум 8 признаков и 5 ограничений. Координаты нормализованы в диапазоне 0..1, начало слева сверху; `region=null` означает глобальное наблюдение. Оценки: `likely_ai` >=65, `likely_real` <=35, `uncertain` между ними. При нехватке деталей возвращаются `probability=null` и `assessment=insufficient_detail`; такой ответ не добавляет число в итог. Пустой `signals` не означает доказанную подлинность.

Интерфейс показывает обоснование, список признаков и кликабельные приблизительные рамки, альтернативные объяснения и JSON. Это объяснение наблюдений, а не скрытая цепочка рассуждений. Vision остаётся одним семантическим сигналом в существующем среднем, без двойного учёта.

Vision может путать обычную программную графику с генеративным ИИ: при проверке подключения изображение из квадрата, круга и подписи, созданное Pillow, получило 99%. Этот пример подтверждает работу транспорта, но показывает false positive и не заменяет benchmark; пороги и формула по нему не менялись.

Проверки без чтения `.env` и без реальных облачных запросов:

```bash
PYTHON_DOTENV_DISABLED=1 .venv/bin/python test_main.py
PYTHON_DOTENV_DISABLED=1 .venv/bin/python test_services.py
PYTHON_DOTENV_DISABLED=1 .venv/bin/python test_chatgpt_auth.py
PYTHON_DOTENV_DISABLED=1 .venv/bin/python test_forensics.py
PYTHON_DOTENV_DISABLED=1 .venv/bin/python test_local_model.py
node test_frontend.js
```

## Ограничение памяти

Численные forensic-проверки всегда работают с уменьшенной копией изображения: максимум 1024 px по длинной стороне, а FFT — максимум 512 px. Изображения больше 40 мегапикселей отклоняются до полной декомпрессии. Локальная ONNX-модель запускается на каждый запрос в отдельном процессе с одним CPU-потоком и таймаутом 28 секунд; после ответа процесс завершается. Linux дополнительно сохраняет лимит адресного пространства 768 MiB. На macOS несовместимый RLIMIT_AS заменён контролем RSS из родительского процесса; один воркер разрешён одновременно.

Родитель проверяет RSS каждые 50 мс и завершает воркер при превышении 768 MiB, невозможности контролировать память или таймауте. Это программный контроль: между измерениями возможно краткое превышение, а не жёсткий kernel limit на macOS. Лимит CPU 20/22 секунды и SHA-256 весов сохранены. В PNG/JPEG smoke-проверках на macOS arm64 inference занял около 1,5-2,1 секунды с пиком RSS около 175 MiB. Для сильно вытянутых изображений центральная область преобразуется сразу в 384x384 без огромного промежуточного ресайза. Обычный preprocessing, калибровка и порог не менялись.

Если воркер не ответил, в строке локальной модели показывается "Ошибка", причина доступна в подробном отчёте. Строка с названием ChatGPT, моделью и лимитами удалена из основного интерфейса; обоснование модели выводится один раз.

Процент в интерфейсе - скрининговая сводка доступных моделей и признаков происхождения, а не доказательство. Если нет ни вероятностных ответов, ни положительных признаков AI-происхождения, показывается "Недостаточно данных", а не вводящие в заблуждение 0%.
