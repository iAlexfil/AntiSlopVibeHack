# AGENTS.md — контекст и правила разработки AntiSlop

Этот файл — основная рабочая память проекта для AI-агентов и разработчиков. Перед изменениями прочитайте его целиком. Если код расходится с этим документом, сначала проверьте фактическое поведение, затем синхронно исправьте код, тесты, README и этот файл.

## 1. Миссия проекта

AntiSlop — MVP веб-сервиса, который оценивает вероятность того, что изображение создано или существенно изменено генеративным ИИ.

Главные принципы:

- выдавать одно понятное итоговое число;
- показывать отдельные оценки по источникам сигнала;
- не выдавать отсутствие метаданных за доказательство подлинности;
- называть результат скрининговой вероятностью, а не доказательством;
- объединять независимые методы: provenance, локальную ML-модель, внешние API и пиксельную криминалистику;
- не допускать OOM ради небольшого прироста качества;
- хранить API-ключи только на сервере;
- сохранять возможность полностью локальной проверки.

Пользователь общается по-русски и предпочитает быстрые практичные изменения без лишней церемонии. Интерфейс и пользовательские сообщения должны оставаться русскоязычными.

## 2. Текущее состояние продукта

Стек:

- FastAPI;
- обычные HTML/CSS/JavaScript без frontend-фреймворка;
- Pillow + NumPy для локальной криминалистики;
- официальный `c2pa-python` для Content Credentials;
- ONNX Runtime для локального классификатора;
- HTTPX для внешних API.

Текущий пользовательский сценарий:

1. Изображение выбирается, перетаскивается или вставляется через `Ctrl/Command + V`.
2. Сервер выполняет локальные проверки и запускает ONNX-модель в изолированном процессе.
3. При включённом переключателе параллельно вызываются только API с настроенными ключами.
4. Интерфейс показывает одну итоговую вероятность.
5. Ниже выводится разбивка по пяти направлениям:
   - локальная ML-модель;
   - смысловой анализ;
   - специализированные внешние детекторы;
   - вотермарки и происхождение;
   - пиксельные аномалии.
6. Полный технический отчёт закрыт по умолчанию и раскрывается через `<details>`.

Важно: проценты в разбивке показывают силу конкретного сигнала. Они не являются независимыми калиброванными вероятностями и не обязаны совпадать с итогом.

Поток данных:

```text
browser image

  -> browser rendering
```

## 4. Контракт итоговой оценки

`services.merge_service_results()` является текущим источником истины для итоговой оценки.

В расчёт `generation_probability` входят:

- все успешные вероятностные ответы моделей и API;
- дополнительный provenance-сигнал `0.99`, если валидный C2PA указывает на генеративный источник;
- provenance-сигнал `0.95`, если найдены сигнатура генератора или параметры генерации.

Сейчас используется простое среднее. Это MVP, а не научно откалиброванный ансамбль.

Правила отображения:

- итог никогда не показывается как абсолютные `0%` или `100%`;
- отображаемый диапазон при наличии оценки: `1–99%`;
- если ни одна вероятностная модель не ответила, показывается «Недостаточно данных», а не `0%`;
- сильное расхождение источников помечается как низкая согласованность;
- пиксельные эвристики пока выводятся в разбивке, но не входят в итоговую вероятность;
- отсутствие вотермарки не уменьшает результат модели и не считается доказательством реальности.

Порог локальной модели: `0.65`. Интерфейс использует общие зоны:

- `>= 65%`: высокая вероятность AI;
- `36–64%`: неоднозначный результат;
- `<= 35%`: низкая вероятность AI.

Не меняйте веса, пороги или формулу по одному удачному/неудачному изображению. Сначала добавьте воспроизводимый evaluation set и измерьте false positive/false negative trade-off.

## 5. Выбранная локальная модель

Используется:

- Hugging Face: `Thermostatic/community-forensics-frontier-detector-2026-08`;
- архитектура: Community Forensics ViT-S/16, вход `384 × 384`;
- artifact: FP16 ONNX;
- лицензия модели: MIT;
- размер файла: `43,778,110` байт, около `41.8 MiB`;
- SHA-256: `d75791ba2fa59146025d342cfaafa9ddeab24af117642a94f752ee4c1619375d`;
- классы: `0 = real`, `1 = AI-generated`;
- preprocessing: RGB, короткая сторона `440`, center crop `384`, ImageNet normalization;
- calibrator: slope `1.0`, intercept `-0.7403357915937764`;
- calibrated threshold: `0.65`;
- эквивалентная raw-logit граница из model card: `1.359375`.

Почему выбрана она:

- обучалась с учётом большого числа старых и новых генераторов;
- опубликован компактный ONNX artifact;
- разрешает коммерческое использование по MIT;
- работает на CPU без PyTorch;
- на пользовательском эталонном изображении с котом-верблюдом на пляже дала `0.9999` AI;
- inference на этом изображении занял примерно `0.8 секунды`;
- наблюдавшийся peak RSS воркера — около `214 MiB`;
- модель лучше подошла к текущему примеру, чем остальные протестированные веса.

Ограничения:

- это whole-image classifier, он слабее на маленьких синтетических вставках;
- устойчивость падает после сильного ресайза, JPEG laundering и recapture;
- опубликованные метрики относятся в основном к development/calibration evaluation;
- детектор может быстро устаревать на новых генераторах;
- высокий score не доказывает происхождение;
- сюрреалистичный, сильно обработанный или графический реальный контент может давать false positive.

Модель обязательно проверяется по SHA-256 перед запуском. Не отключайте checksum ради удобства.

## 7. Локальная криминалистика

`forensics.py` выполняет:

- проверку C2PA через официальный CAI SDK без remote manifest fetch;
- ELA для JPEG;
- анализ согласованности шумового остатка;
- FFT / частотный спектр;
- блочный поиск повторяющихся высокочастотных паттернов;
- EXIF-проверки камеры, software и даты;
- SHA-256, perceptual hash и difference hash;
- генерацию уменьшенных diagnostic maps для подробного отчёта.

Эти эвристики неспецифичны для ИИ. Они реагируют также на ретушь, монтаж, ресайз, компрессию, орнаменты и апскейл. Не превращайте один `review`-сигнал в уверенный AI verdict.

Ручные/metadata-маркеры в `main.py` покрывают Midjourney, OpenAI/DALL·E/GPT Image, Stable Diffusion/ComfyUI/A1111, Firefly, Imagen/Gemini, Ideogram, Leonardo, Runway, NovelAI, Flux, Canva, Microsoft Designer, NightCafe и Playground AI.

### Анализ серии (`POST /api/analyze-set`)

`multipart files[]` (2–6 снимков, ≤ 20 МБ каждый), `mode=scene|person`, `remote` — как у одиночного анализа. Каждый снимок проходит обычный `run_pipeline`, затем `multiview_worker.py`.

Сцена (все пары снимков, анализ на ≤ 1024 px):

- SIFT 4000 точек, взаимный ratio-test 0.75, затем `findFundamentalMat` и `findHomography` через `USAC_MAGSAC`;
- статусы пары: `consistent_3d`, `inconsistent`, `planar` (H объясняет ≥ 85% — возможна съёмка экрана/распечатки), `near_duplicate`, `no_overlap` (< 15 согласованных точек — шум), `weak`;
- cheirality: essential matrix + `recoverPose` с фокусным из `FocalLengthIn35mmFilm` или допущением 28 мм; < 75% точек перед камерами → `inconsistent`;
- карта несогласованных зон: сетка 16×16, текстурные ячейки внутри оболочки inliers без единого inlier;
- вердикт `consistent`, только если граф согласованных пар связывает все снимки.

Человек: YuNet → самый крупный face, `alignCrop` 112×112, SFace cosine (порог 0.363 из документации OpenCV, < 0.25 — разные люди). «Вклеенное лицо»: SSIM центральной части после ECC-довыравнивания ≥ 0.85, разница позы (SQPnP по 5 точкам) ≤ 4° и фоны без общих деталей (SIFT по маске без лица). Лицо против фона: локальная модель отдельно на кропе лица и на самой большой полосе кадра без лица; расхождение ≥ 0.6 — слабый сигнал (модель обучена на целых кадрах; размытие лица давало ложный AI, поэтому не используется).

EXIF серии: одна камера, интервал ≤ 30 мин, GPS ≤ 200 м, последовательные номера файлов — слабые положительные; разные устройства — слабый отрицательный; отсутствие EXIF нейтрально.

`series.finalize`: если итог ≥ 65% у большинства снимков, вердикт `consistent` понижается до `insufficient` — согласованность не отменяет AI-сигнал (AI-видео даёт согласованные кадры). Все пороги стартовые, не калиброваны: нужен evaluation-набор серий.

Поддержанные адаптеры:

Текущий default для OpenAI Vision: `gpt-6-luna`, но он задаётся через env и может быть заменён без изменения кода. Vision-анализ ищет семантические противоречия, анатомические ошибки, физику, повторения и проблемы текста. Перед изменением модели или схемы обязательно сверяйтесь с актуальной официальной документацией API.

Известные недоступные интеграции:

- Illuminarty: нет стабильного общего публичного API-контракта;
- Google SynthID image detector: нет доступного публичного detector API для произвольного backend-вызова.

Правила секретов:

- реальные ключи находятся только в `.env`;
- `.env` запрещено коммитить;
- `.env.example` содержит только пустые значения;
- ключи нельзя возвращать клиенту, логировать или вставлять в URL;
- отсутствие ключа должно давать `not_configured`, а не ошибку всего анализа;
- внешний API вызывается только если пользователь оставил включённым переключатель remote analysis.

## 9. Ограничения ресурсов — не ломать

Защита от OOM является обязательной частью продукта.

Текущие ограничения:

- максимальный upload: `20 MiB`;
- максимальное декодированное изображение: `40 MP`;
- forensic preview: максимум `1024 px` по длинной стороне;
- FFT: максимум `512 px`;
- diagnostic maps: максимум `640 px`;
- ML input: `384 × 384`;
- ML запускается в отдельном процессе на каждый анализ;
- `RLIMIT_AS`: `768 MiB`;
- `RLIMIT_CPU`: `20 + 2` секунды;
- parent timeout: `28` секунд;
- ONNX intra/inter-op threads: `1`;
- CPU memory arena отключена;
- `OMP`, `OpenBLAS` и `MKL` ограничены одним потоком;
- `LOCAL_MODEL_GATE = asyncio.Semaphore(1)`: одновременно разрешён только один ML worker; multiview worker делит тот же семафор.
- Серия: 2–6 снимков ≤ 20 МБ; multiview worker `RLIMIT_AS` 768 MiB, `RLIMIT_CPU` 40 + 2 с, parent timeout 50 с, `cv2.setNumThreads(1)`, JPEG декодируется через `draft` (≤ 2048 px), анализ на ≤ 1024 px. Замер: 6 снимков с двумя по 40 MP — peak RSS 306 MiB, ~11 с.

Не загружайте модель постоянно в FastAPI-процесс без измерений. Не запускайте несколько тяжёлых моделей параллельно. Если добавляется ensemble, выполняйте модели последовательно в одном контролируемом worker или докажите бенчмарком, что новый peak RSS безопасен.

Любое изменение ML pipeline должно логически сохранять:

1. bounded input;
2. timeout;
3. memory limit;
4. checksum модели;
5. отсутствие GPU requirement;
6. корректный fallback при падении worker.

### Оценка качества (`evaluation/`)

```bash
.venv/bin/pip install -r requirements-eval.txt     # pyarrow, только для выгрузки
.venv/bin/python -m evaluation fetch --row-groups 3   # ~444 оригинала из OpenFake test, ~300 МБ, лимит --budget-mb 450
.venv/bin/python -m evaluation run                    # original + jpeg75 + social1080, отчёт в eval_reports/<время>/report.md
.venv/bin/python -m evaluation run --folder my_set    # свой набор: my_set/real/**, my_set/ai/<генератор>/**
```

- Источник: `ComplexDataLab/OpenFake`, config `core`, split `test`, лицензия CC BY-NC 4.0 — только для внутренней оценки, не коммитить и не распространять.
- Картинки берутся из parquet через HTTP Range с проверкой `image_sha256`; JPEG из datasets-server не используются, потому что они пережаты.
- Утечка: модель обучалась на OpenFake real (LAION/Pexels), ImageNet и генераторах OpenFake. Решения принимайте по срезам «без реальных фото из обучения» (DOCCI) и «генераторы новее модели», а не по общему числу.
- Предсказания кэшируются в `eval_reports/predictions-<pipeline_version>.jsonl`; версия — хеш файлов пайплайна и модели.
- `--remote` отправляет изображения во внешние API и тратит квоты; по умолчанию выключен.
- `eval_data/` и `eval_reports/` в `.gitignore`.

Для model changes нужен хотя бы небольшой фиксированный набор:

- реальные фотографии из проверяемого источника;
- AI-изображения разных генераторов;
- JPEG/WebP laundering;
- ресайз и скриншоты;
- иллюстрации и цифровое искусство;
- фотомонтаж и сильно обработанные реальные фото;
- изображения с маленькой AI-вставкой.

Не называйте один synthetic sample «датасетом» и не подбирайте порог под него.

## 11. Известные технические долги

- Итоговый ансамбль использует простое среднее и не откалиброван на собственном validation set.
- Evaluation есть (`python -m evaluation`), но единственный публичный источник — OpenFake, на котором модель частично обучалась; нужен независимый набор реальных фото и свежих генераторов.
- Нет OCR-анализа и отдельной оценки искажённого текста.
- Нет локализации подозрительных областей; модель классифицирует всё изображение (для серий есть только карта несогласованных зон).
- Пороги анализа серии не откалиброваны: нет evaluation-набора серий (реальные multi-view, AI-«другие ракурсы», face swap, PhotoMaker/InstantID). Проверено только на синтетике и примерах OpenCV.
- Анализ серии: нет OCR кода челленджа, нет родинок/шрамов (MediaPipe), сравнение по смыслу (VLM) не подключено.
- Нет rate limiting и очереди для внешних API.
- Нет кэша по SHA-256, поэтому одинаковые файлы анализируются повторно.
- Diagnostic maps возвращаются как base64 в JSON, что увеличивает ответ.
- Модель хранится прямо в Git-репозитории; Git LFS пока не используется.
- Старые CSS-файлы не подключены, но ещё не удалены.
- Нет контейнеризации и production deployment manifest.

## 15. Журнал существенных решений

### 2026-10-25 — анализ серии снимков (сцена и человек)

- Добавлены `POST /api/analyze-set`, `multiview.py`, `multiview_worker.py`, `series.py`, режим «Серия фото» в интерфейсе и `test_multiview.py`; общий `run_pipeline` используется для каждого снимка.
- Новые зависимости: `opencv-python-headless` (Apache 2.0), `python-multipart`; модели YuNet (MIT, 0.2 МБ) и SFace (Apache 2.0, 37 МБ) с проверкой SHA-256.
- Почему: одиночный детектор ошибается уверенно (16% FPR на DOCCI); несколько согласованных ракурсов подделать намного дороже, и проверка работает без внешних API.
- Проверено: стереопара Middlebury aloe → `consistent` (94% inliers, 99.8% cheirality); нелинейно «поплывшая» вариация → `inconsistent` (cheirality 6%); граффити/коробка → `planar`; вклеенное лицо Lena на двух фонах → `inconsistent`; синтетический параллакс и физически невозможный сдвиг слоёв в тестах; desktop/mobile browser flow без JS-ошибок.
- Найдено и исправлено по ходу: совпадения на одинаковом лице выдавали пару за дубликат (фон теперь сравнивается без лица); 10 «согласованных» точек на несвязанных текстурах — шум (порог 15); размытие лица давало 81% AI фону (заменено чистой полосой фона).
- Ограничения: пороги не калиброваны; real multi-view с телефонов ещё не прогоняли; AI-видео может пройти геометрию — поэтому AI-оценки снимков показываются отдельно и понижают вердикт.
