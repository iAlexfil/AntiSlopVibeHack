# AGENTS.md — контекст и правила разработки AntiSlop

Этот файл — основная рабочая память проекта для AI-агентов и разработчиков. Перед изменениями прочитайте его целиком. Если код расходится с этим документом, сначала проверьте фактическое поведение, затем синхронно исправьте код, тесты, README и этот файл.

## 1. Миссия проекта

AntiSlop — MVP веб-сервиса, который оценивает вероятность того, что изображение создано или существенно изменено генеративным ИИ.

Главные принципы:

- выдавать одно понятное итоговое число;
- показывать отдельные оценки по источникам сигнала;
- не выдавать отсутствие метаданных за доказательство подлинности;
- называть результат скрининговой вероятностью, а не доказательством;
- объединять независимые методы: provenance, локальную ML-модель, внешние API и пиксельную криминалистику;
- не допускать OOM ради небольшого прироста качества;
- хранить API-ключи только на сервере;
- сохранять возможность полностью локальной проверки.

Пользователь общается по-русски и предпочитает быстрые практичные изменения без лишней церемонии. Интерфейс и пользовательские сообщения должны оставаться русскоязычными.

## 2. Текущее состояние продукта

Стек:

- FastAPI;
- обычные HTML/CSS/JavaScript без frontend-фреймворка;
- Pillow + NumPy для локальной криминалистики;
- официальный `c2pa-python` для Content Credentials;
- ONNX Runtime для локального классификатора;
- HTTPX для внешних API.

Текущий пользовательский сценарий:

1. Изображение выбирается, перетаскивается или вставляется через `Ctrl/Command + V`.
2. Сервер выполняет локальные проверки и запускает ONNX-модель в изолированном процессе.
3. При включённом переключателе параллельно вызываются только настроенные API; смысловой анализ использует отдельную OAuth-сессию ChatGPT.
4. Интерфейс показывает одну итоговую вероятность.
5. Ниже выводится разбивка по пяти направлениям:
   - локальная ML-модель;
   - смысловой анализ;
   - специализированные внешние детекторы;
   - вотермарки и происхождение;
   - пиксельные аномалии.
6. Смысловой анализ показывает наблюдения, объяснения, приблизительные рамки и JSON контракта `1.0`.
7. Полный технический отчёт закрыт по умолчанию и раскрывается через `<details>`.

Интерфейс — тёмный футуристичный лендинг с крупной типографикой Unbounded, холодным голубым акцентом и анимированной перспективной сеткой на Canvas. Первый экран содержит один главный CTA «Проверить изображение», который сразу открывает выбор файла. Форма расположена ниже; после выбора, перетаскивания или вставки интерфейс прокручивается к проверке. На desktop превью и настройки стоят рядом, на mobile — друг под другом. Рекламные слоганы и повторяющиеся оговорки из основного сценария убраны по просьбе пользователя. Под формой — три направления анализа; полный отчёт по-прежнему раскрывается отдельно.

Во время анализа смена файла и переключателя заблокирована, видны scan line и текстовый статус без выдуманного процента прогресса. Ошибки показываются inline с возможностью повторить запрос; клиентский таймаут — 120 секунд. Отдельно отображаются число ответивших моделей и согласованность источников. Для форматов без browser preview (например, TIFF) предусмотрена текстовая замена; анализ остаётся доступен. Интерфейс поддерживает клавиатуру и `prefers-reduced-motion`.

После анализа сохраняется приватный снимок отчёта на 24 часа; в ответ добавляются `report_id` и приватный `pdf_path`. «Поделиться ссылкой» явно публикует его через `POST /api/reports` и создаёт отдельную read-only страницу `/r/{token}` на 30 дней. Повторный клик возвращает ту же ссылку. Ссылка копируется в буфер или остаётся доступной для ручного копирования; текстовая сводка больше не подменяет ссылку. «Скачать PDF» отдаёт настоящий PDF с кириллицей и превью; скачивание приватного PDF не публикует отчёт. При смене исходных данных состояние кнопок/ссылки очищается.

Отчёты сохраняются в SQLite (`.antislop-reports/`, настраивается через `ANTISLOP_REPORTS_DIR`) и переживают перезапуск. Включены только разрешённые поля результата и уменьшенные JPEG без метаданных; имена исходных файлов, EXIF/GPS, параметры генерации и сырые ошибки/API-ответы не сохраняются. По опубликованной ссылке доступны результат и превью. Без публичного размещения адрес доступен только там, где доступен сервер. `PUBLIC_BASE_URL` задаёт публичный origin; иначе используется текущий origin браузера.

После выбора изображения доступен поиск в Яндексе и Google с уже выбранной картинкой. Блок стоит сразу под подробным отчётом, в обычном потоке страницы. По явному нажатию браузер подготавливает небольшую JPEG-копию, отправляет её в Яндекс и открывает выбранную выдачу в новой вкладке; Google использует URL этой копии. Исходный File остаётся неизменным. Поиск доступен до/после анализа и при `remote=false`; сам выбор файла ничего поисковикам не отправляет. Сброс или смена файла отменяют незавершённый поиск и очищают кэш. Копия для текущего файла кэшируется на пять минут.

Важно: проценты в разбивке показывают силу конкретного сигнала. Они не являются независимыми калиброванными вероятностями и не обязаны совпадать с итогом.

## 4. Контракт итоговой оценки

`services.merge_service_results()` является текущим источником истины для итоговой оценки.

В расчёт `generation_probability` входят:

- все успешные вероятностные ответы моделей и API;
- один provenance-сигнал `0.99`, если локальный валидный C2PA указывает на генеративный источник, OpenAI обнаружил SynthID или OpenAI обнаружил C2PA со статусом `trusted` / `valid`;
- provenance-сигнал `0.95`, если найдены сигнатура генератора или параметры генерации.

Сейчас используется простое среднее. Это MVP, а не научно откалиброванный ансамбль.

Прямой поиск в отдельной вкладке не возвращает результаты в AntiSlop и не входит в итоговую вероятность, число ответивших моделей или согласованность источников.

OpenAI Content Provenance API возвращает булевые признаки происхождения без вероятностного score. Его положительный результат и локальный C2PA дают общий сигнал `0.99` без двойного учёта; при его наличии metadata-сигнал `0.95` отдельно не добавляется. Отрицательный `not_detected`, недоверенный/невалидный C2PA и ошибки API не добавляют чисел в среднее и не снижают оценки моделей.

Правила отображения:

- итог никогда не показывается как абсолютные `0%` или `100%`;
- отображаемый диапазон при наличии оценки: `1–99%`;
- если нет ни вероятностных ответов, ни положительных признаков AI-происхождения, показывается "Недостаточно данных", а не `0%`;
- сильное расхождение источников помечается как низкая согласованность;
- пиксельные эвристики пока выводятся в разбивке, но не входят в итоговую вероятность;
- отсутствие вотермарки не уменьшает результат модели и не считается доказательством реальности.

Порог локальной модели: `0.65`. Интерфейс использует общие зоны:

- `>= 65%`: высокая вероятность AI;
- `36–64%`: неоднозначный результат;
- `<= 35%`: низкая вероятность AI.

Не меняйте веса, пороги или формулу по одному удачному/неудачному изображению. Сначала добавьте воспроизводимый evaluation set и измерьте false positive/false negative trade-off.

## 5. Выбранная локальная модель

Используется:

- Hugging Face: `Thermostatic/community-forensics-frontier-detector-2026-08`;
- архитектура: Community Forensics ViT-S/16, вход `384 × 384`;
- artifact: FP16 ONNX;
- лицензия модели: MIT;
- размер файла: `43,778,110` байт, около `41.8 MiB`;
- SHA-256: `d75791ba2fa59146025d342cfaafa9ddeab24af117642a94f752ee4c1619375d`;
- классы: `0 = real`, `1 = AI-generated`;
- preprocessing: RGB, короткая сторона `440`, center crop `384`, ImageNet normalization;
- calibrator: slope `1.0`, intercept `-0.7403357915937764`;
- calibrated threshold: `0.65`;
- эквивалентная raw-logit граница из model card: `1.359375`.

Почему выбрана она:

- обучалась с учётом большого числа старых и новых генераторов;
- опубликован компактный ONNX artifact;
- разрешает коммерческое использование по MIT;
- работает на CPU без PyTorch;
- на пользовательском эталонном изображении с котом-верблюдом на пляже дала `0.9999` AI;
- inference на этом изображении занял примерно `0.8 секунды`;
- наблюдавшийся peak RSS воркера — около `214 MiB`;
- модель лучше подошла к текущему примеру, чем остальные протестированные веса.

Ограничения:

- это whole-image classifier, он слабее на маленьких синтетических вставках;
- устойчивость падает после сильного ресайза, JPEG laundering и recapture;
- опубликованные метрики относятся в основном к development/calibration evaluation;
- детектор может быстро устаревать на новых генераторах;
- высокий score не доказывает происхождение;
- сюрреалистичный, сильно обработанный или графический реальный контент может давать false positive.

Модель обязательно проверяется по SHA-256 перед запуском. Не отключайте checksum ради удобства.

## 7. Локальная криминалистика

`forensics.py` выполняет:

- проверку C2PA через официальный CAI SDK без remote manifest fetch;
- ELA для JPEG;
- анализ согласованности шумового остатка;
- FFT / частотный спектр;
- блочный поиск повторяющихся высокочастотных паттернов;
- EXIF-проверки камеры, software и даты;
- SHA-256, perceptual hash и difference hash;
- генерацию уменьшенных diagnostic maps для подробного отчёта.

Эти эвристики неспецифичны для ИИ. Они реагируют также на ретушь, монтаж, ресайз, компрессию, орнаменты и апскейл. Не превращайте один `review`-сигнал в уверенный AI verdict.

Ручные/metadata-маркеры в `main.py` покрывают Midjourney, OpenAI/DALL·E/GPT Image, Stable Diffusion/ComfyUI/A1111, Firefly, Imagen/Gemini, Ideogram, Leonardo, Runway, NovelAI, Flux, Canva, Microsoft Designer, NightCafe и Playground AI.

### Анализ серии (`POST /api/analyze-set`)

`multipart files[]` (2–6 снимков, ≤ 20 МБ каждый), `mode=scene|person`, `remote` — как у одиночного анализа. Каждый снимок проходит обычный `run_pipeline`, затем `multiview_worker.py`.

Сцена (все пары снимков, анализ на ≤ 1024 px):

- SIFT 4000 точек, взаимный ratio-test 0.75, затем `findFundamentalMat` и `findHomography` через `USAC_MAGSAC`;
- статусы пары: `consistent_3d`, `inconsistent`, `planar` (H объясняет ≥ 85% — возможна съёмка экрана/распечатки), `near_duplicate`, `no_overlap` (< 15 согласованных точек — шум), `weak`;
- cheirality: essential matrix + `recoverPose` с фокусным из `FocalLengthIn35mmFilm` или допущением 28 мм; < 75% точек перед камерами → `inconsistent`;
- карта несогласованных зон: сетка 16×16, текстурные ячейки внутри оболочки inliers без единого inlier;
- вердикт `consistent`, только если граф согласованных пар связывает все снимки.

Человек: YuNet → самый крупный face, `alignCrop` 112×112, SFace cosine (порог 0.363 из документации OpenCV, < 0.25 — разные люди). «Вклеенное лицо»: SSIM центральной части после ECC-довыравнивания ≥ 0.85, разница позы (SQPnP по 5 точкам) ≤ 4° и фоны без общих деталей (SIFT по маске без лица). Лицо против фона: локальная модель отдельно на кропе лица и на самой большой полосе кадра без лица; расхождение ≥ 0.6 — слабый сигнал (модель обучена на целых кадрах; размытие лица давало ложный AI, поэтому не используется).

EXIF серии: одна камера, интервал ≤ 30 мин, GPS ≤ 200 м, последовательные номера файлов — слабые положительные; разные устройства — слабый отрицательный; отсутствие EXIF нейтрально.

`series.finalize` возвращает независимые `consistency` и `ai_assessment`: согласованность ракурсов/личности и AI-оценки кадров. Основная карточка интерфейса использует `consistency.verdict`, `label`, `headline`, `detail`; высокие AI-оценки больше не заменяют успешное сравнение общим «Недостаточно данных». `checked_images`/`checked_pairs` означают сопоставленные, а не обязательно согласованные снимки/пары. Причины отсутствия вывода разделены на дубликаты, плоскую геометрию, частичный граф, отсутствие перекрытия, слабые совпадения, отсутствующие/мелкие/неоднозначные лица. Рекомендации строятся по результату сравнения, независимо от AI-оценок.

Для совместимости прежние верхнеуровневые `verdict` и `headline` пока сохраняют объединённое поведение: если итог ≥ 65% у большинства оценённых снимков, `consistent` понижается до `insufficient`. Новые клиенты должны использовать две независимые оценки. Согласованность не отменяет AI-сигнал: AI-видео тоже даёт согласованные кадры. В режиме человека непроверенное мелкое лицо исключает вывод обо всей серии. Параметры серии заблокированы во время запроса, изменение набора/режима/remote скрывает устаревший отчёт. Все пороги стартовые, не калиброваны: нужен evaluation-набор серий.

## 8. Внешние сервисы и секреты

Поддержанные адаптеры:

| ID | Сервис | Переменные окружения |
| --- | --- | --- |
| `openai_vision` | ChatGPT Vision, Responses API с OAuth и лимитами плана | OAuth через `chatgpt_login.py`; опционально `CHATGPT_VISION_MODEL` |
| `synthid` | OpenAI Content Provenance API, SynthID / C2PA | `OPENAI_API_KEY` |
| `hive` | Hive AI-generated media detection | `HIVE_API_KEY` |
| `sightengine` | Sightengine genai model | `SIGHTENGINE_API_USER`, `SIGHTENGINE_API_SECRET` |
| `aiornot` | AI or Not image report | `AIORNOT_API_KEY` |
| `wasitai` | WasItAI classifier | `WASITAI_API_KEY` |

Текущий default для ChatGPT Vision: `gpt-6-luna`, но он задаётся через env и может быть заменён без изменения кода. Vision-анализ ищет семантические противоречия, анатомические ошибки, физику, повторения и проблемы текста. Перед изменением модели или схемы обязательно сверяйтесь с актуальной официальной документацией API.

Адаптер `_openai_provenance` вызывает `POST https://api.openai.com/v1/content_provenance_checks` с multipart-полем `file` и ключом `OPENAI_API_KEY`, предназначенным только для этой проверки. В API передаются исходные байты PNG/JPEG/WebP с MIME, определённым по содержимому. Ресайз и перекодирование перед проверкой запрещены, чтобы не повреждать метку и C2PA. Другие форматы не отправляются. Запрос выполняется только при `remote=true`, с таймаутом 25 секунд и без автоматических повторов.

Сервис проверяет только поддерживаемые OpenAI сигналы SynthID и C2PA, а не все изображения Google или других генераторов. Результаты отдельных проверок и доступные `model`, `generated_at`, `issuer`, `validation_state` сохраняются в полном отчёте. `not_detected` нейтрален. HTTP 400 означает неподдерживаемый/заблокированный файл, 404 - отсутствие доступа организации, 429 - лимит запросов; эти ответы и другие сбои не прерывают анализ. Перед изменением контракта сверяйтесь с [руководством OpenAI](https://developers.openai.com/api/docs/guides/content-provenance) и [справочником API](https://developers.openai.com/api/reference/resources/content_provenance_checks/methods/create).

Прямой web-поиск выполняется в браузере без платных API и ключей. Проверен текущий клиентский контракт Яндекса: `POST https://ya.ru/images-apphost/image-download?cbird=111&images_avatars_size=preview&images_avatars_namespace=images-cbir` с raw JPEG Blob, `credentials=omit` и разрешённым CORS. Ответ содержит числовой `image_shard`, строковый `image_id` и HTTPS-адрес на `avatars.mds.yandex.net`. Выдача открывается на `https://ya.ru/images/search` с `rpt=imageview`, `cbir_id=<shard>/<id>`, `url=<orig image URL>` и `tabInt=1`. Фактическая выдача с похожими изображениями и сайтами проверена. При `type=captcha` используется только проверенный HTTPS-адрес Яндекса из `captcha["captcha-page"]`, без обхода проверки.

Google использует подтверждённый GET `https://lens.google.com/v3/upload` с `url=<orig image URL>`, `ep=gsbubu`, `st`, `authuser=0`, `hl=ru`, `vpw`, `vph`. Нативный cross-site POST возвращал 403 даже со всеми полями официального UI и удалён. GET доходит до Google Search с HTTP 200; в проверочной сети затем появляется капча (429), поэтому реальные совпадения Google пока не подтверждены. Оба перехода используют копию, загруженную в Яндекс, что явно написано возле кнопок. Новая вкладка резервируется внутри пользовательского нажатия с `opener=null`; отправка и переход ограничены таймаутами, при ошибке/сбросе ещё пустая вкладка закрывается. Это проверенные текущие браузерные интерфейсы, не стабильные developer APIs; при изменениях требуется повторная проверка.

Смысловой анализ не читает `OPENAI_API_KEY` и не использует API-key fallback. Отдельный вход: `.venv/bin/python chatgpt_login.py`. Механизм перенесён из предоставленных пользователем `jarvis/chatgpt_login.py` и `jarvis/chatgpt_auth.py`: динамический client ID, стабильный host ID, PKCE, state/nonce, RS256/JWKS, проверка account identity и scopes. Файлы `.antislop-auth/registration.json` и `credentials.json` имеют права 0600, каталог 0700, всё хранилище исключено из Git. Сессию Jarvis или личного Codex читать/копировать не нужно. Refresh сериализован flock, ротация сохраняется даже при отмене запроса. `/api/vision/auth` возвращает только безопасный локальный статус, модель и подсказку входа.

Запросы Vision: публичный `/v1/responses`, OAuth bearer, `store=false`, `stream=true`, без инструментов и платного fallback. Успех принимается только после `response.completed`, ошибки/обрыв/лимиты из SSE обрабатываются отдельно. Внешний режим остаётся обязательным: `remote=false` не запускает OAuth refresh и не отправляет изображение наружу. Официальный контракт: [вход](https://developers.openai.com/siwc/token-sharing-open-source/sign-in), [inference](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference).

JSON `VisualAnalysis` версии `1.0`: probability 0..100 или null, assessment, explanation, максимум 8 signals с категорией, наблюдением, кратким объяснением, альтернативной причиной, силой и region; максимум 5 limitations. Рамки нормализованы 0..1 относительно изображения после EXIF transpose; region=null для глобального наблюдения. `insufficient_detail` требует probability=null и не добавляет численную оценку. Контракт одновременно задаёт structured output и строгую серверную валидацию. Краткое обоснование относится к видимым признакам, не к скрытой цепочке рассуждений. Формула среднего не менялась, добавленного второго semantic provider нет.

Известные недоступные интеграции:

- Illuminarty: нет стабильного общего публичного API-контракта;
- Полное покрытие SynthID для Google и других генераторов: используемый OpenAI API его не обещает; для расширения нужен отдельный официально поддерживаемый контракт.

Правила секретов:

- API-ключи находятся только в `.env`; OAuth-сессия отдельно в `.antislop-auth/`, никогда не в клиентском ответе;
- `.env` запрещено коммитить;
- `.env.example` содержит только пустые значения;
- ключи нельзя возвращать клиенту, логировать или вставлять в URL;
- отсутствие ключа должно давать `not_configured`, а не ошибку всего анализа;
- внешний API вызывается только если пользователь оставил включённым переключатель remote analysis.

## 9. Ограничения ресурсов — не ломать

Защита от OOM является обязательной частью продукта.

Текущие ограничения:

- максимальный upload: `20 MiB`;
- максимальное декодированное изображение: `40 MP`;
- forensic preview: максимум `1024 px` по длинной стороне;
- FFT: максимум `512 px`;
- diagnostic maps: максимум `640 px`;
- browser preview для внешнего поиска: максимум `1280 px`, JPEG до `2 MiB`, исходник до `40 MP`;
- внешний поиск: таймаут отправки `25` секунд, общий таймаут `60` секунд, только одна отправка за раз;
- ML input: `384 × 384`;
- Vision preview: JPEG до `1280 px`, один запрос одновременно, общий timeout `90` секунд, сетевой timeout `60` секунд, поток до `2 MiB`;
- ML запускается в отдельном процессе на каждый анализ;
- Linux `RLIMIT_AS`: `768 MiB`; macOS не использует несовместимый лимит виртуального адресного пространства;
- parent RSS watchdog: `768 MiB`, опрос каждые `50 ms`, kill и сбор процесса при превышении, ошибке мониторинга или timeout;
- RSS watchdog является программным контролем с возможным кратким превышением между опросами, а не жёстким kernel limit на macOS;
- промежуточный ML-resize ограничен `40 MP`; при экстремальных пропорциях центральная область сразу приводится к `384x384`;
- `RLIMIT_CPU`: `20 + 2` секунды;
- parent timeout: `28` секунд;
- ONNX intra/inter-op threads: `1`;
- CPU memory arena отключена;
- `OMP`, `OpenBLAS` и `MKL` ограничены одним потоком;
- `LOCAL_MODEL_GATE = asyncio.Semaphore(1)`: одновременно разрешён только один ML worker; multiview worker делит тот же семафор.
- Серия: 2–6 снимков ≤ 20 МБ; multiview worker `RLIMIT_AS` 768 MiB, `RLIMIT_CPU` 40 + 2 с, parent timeout 50 с, `cv2.setNumThreads(1)`, JPEG декодируется через `draft` (≤ 2048 px), анализ на ≤ 1024 px. Замер: 6 снимков с двумя по 40 MP — peak RSS 306 MiB, ~11 с.
- Сохранённый отчёт: максимум 6 JPEG-превью (800 px одиночное / 480 px серия), до 256 КиБ каждое, документ до 2 МиБ. Основной SQLite-файл ограничен 128 МиБ и 256 живыми записями; journal временный. Черновик — 24 часа, опубликованный отчёт — 30 дней; живые публичные отчёты не вытесняются.
- Подготовка превью отчёта и рендер PDF имеют отдельные семафоры по одному заданию; PDF загружает снимок только после получения семафора. Исходные изображения и metadata в PDF не попадают, только ограниченные JPEG-превью и разрешённый текст. Хранилище вне Git; при его ошибке анализ остаётся доступным.

Не загружайте модель постоянно в FastAPI-процесс без измерений. Не запускайте несколько тяжёлых моделей параллельно. Если добавляется ensemble, выполняйте модели последовательно в одном контролируемом worker или докажите бенчмарком, что новый peak RSS безопасен.

Любое изменение ML pipeline должно логически сохранять:

1. bounded input;
2. timeout;
3. memory limit;
4. checksum модели;
5. отсутствие GPU requirement;
6. корректный fallback при падении worker.

## 11. Известные технические долги

- Прямой поиск зависит от текущих браузерных интерфейсов Яндекса и Google, которые могут измениться. Google может запрашивать капчу/вход. Выдача открывается снаружи и не возвращается в анализ; калибровка по найденным страницам не выполняется.
- `test_frontend.js` из upstream использует заглушку прежнего DOM, не поддерживает новые DOM API и состояния редизайна; требуется адаптация. В текущей UI-задаче тесты не менялись по просьбе пользователя, сценарии проверены в настоящем браузере.
- На macOS память ML контролирует parent RSS watchdog с интервалом 50 мс; краткий overshoot возможен. Для жёсткой изоляции памяти нужна среда с kernel-enforced limits. Ошибка RLIMIT_AS и единиц ru_maxrss исправлена.
- Итоговый ансамбль использует простое среднее и не откалиброван на собственном validation set.
- Evaluation есть (`python -m evaluation`), но единственный публичный источник — OpenFake, на котором модель частично обучалась; нужен независимый набор реальных фото и свежих генераторов.
- Vision может путать обычную программную графику с генеративным ИИ; численная оценка и сила наблюдений требуют отдельной проверки и калибровки.
- Нет OCR-анализа и отдельной оценки искажённого текста.
- Локальный классификатор не локализует области; Vision даёт только приблизительные рамки, их точность не измерена. Для серий есть карта несогласованных зон.
- Пороги анализа серии не откалиброваны: нет evaluation-набора серий (реальные multi-view, AI-«другие ракурсы», face swap, PhotoMaker/InstantID). Проверено только на синтетике и примерах OpenCV.
- Верхнеуровневый legacy `verdict` серии объединяет согласованность и AI-сигналы; интерфейс использует новые независимые `consistency` и `ai_assessment`. Для удаления legacy-поведения потребуется отдельная версия API.
- Анализ серии: нет OCR кода челленджа, нет родинок/шрамов (MediaPipe), сравнение по смыслу (VLM) не подключено.
- Нет rate limiting и очереди для внешних API.
- Нет кэша по SHA-256, поэтому одинаковые файлы анализируются повторно.
- Diagnostic maps возвращаются как base64 в JSON, что увеличивает ответ.
- Модель хранится прямо в Git-репозитории; Git LFS пока не используется.
- Старые CSS-файлы не подключены, но ещё не удалены.
- Нет контейнеризации и production deployment manifest.
